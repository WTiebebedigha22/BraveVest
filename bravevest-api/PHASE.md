## Data model decisions

**`Project` stays.** Funding requests live alongside, not on top of. Existing investor flows keep working. Unifying is a Phase 6+ decision.

**Status flow:**
```
DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED → PUBLISHED → FUNDED → CLOSED
                              ↘ REJECTED            ↘ CANCELLED
                                                    ↘ DEFAULTED
```

Transitions enforced in Phase 2 service layer.

**Borrower and investor are roles on the same `User` row.** A user can be both — dual-role is supported by the schema. The UI decides which dashboard to show.

## Vocabulary

BraveVest uses **Credit** as the section name for anything a borrower side of
the platform touches. Underneath, a funded request is a peer-to-peer loan:
the borrower receives capital from individual investors and repays over the
agreed term at the stated return.

UI copy:
- Dashboard toggle: **Investing / Credit**
- Borrower CTA: **Request funding**
- Explanation on the request form: "You're requesting funding from individual investors. Each commitment is a peer-to-peer loan."
- Investor-side note: "When you commit, you're funding a peer-to-peer loan."

Data model, API paths, and status enum names keep the internal term `funding`
(`FundingRequest`, `/api/funding/*`). Only user-facing copy uses "Credit".
